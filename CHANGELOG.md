# Changelog

## [Unreleased]

### Added

- Operator dashboard suite: Overview (SLO indicators from new recording rules sorotrail:http_availability:ratio5m, sorotrail:http_latency:p95_5m, sorotrail:ingestion_lag:max), Ingestion, Read path and Storage dashboards under deploy/grafana/, each panel annotated with what good looks like. scripts/validate_monitoring.py now checks every dashboard (metric existence, recording-rule references, unique uid, panel descriptions) and that every alert has a dashboard_url; the runbook maps alerts to dashboards. Per-tenant, delivery and retention views are not included. (#1258)
- Bulk export (`GET /events.csv` and `GET /contracts/{id}/export`) now says how it ended. A complete export sets the `X-Export-Status: complete` and `X-Export-Rows` trailers; one that stops after rows were sent (a store failure, the request timeout, a write error) aborts the connection instead of ending the body, so a truncated file can no longer look whole, and `terminator=true` adds the same end marker in-band (a final NDJSON line, or a `#export-complete,N` CSV record). A failure before the first NDJSON row is now a real 500 instead of an empty 200. CSV cells that a spreadsheet would run as a formula are prefixed with a single quote, exported rows count against the tenant's events-served usage, and `Recoverer` lets `http.ErrAbortHandler` through. Memory stays flat: a test streams 85 MiB at a 3 MiB heap peak. (#1243)
- The event, contract and address read endpoints now answer conditional requests. A 200 carries a strong `ETag` (a hash of the response body, so scope and filters are part of it) and `If-None-Match` is answered with `304 Not Modified` and no body when nothing changed; live listings stay `no-cache` so clients revalidate cheaply on every poll. `/health`, `/stats`, errors and streamed responses are not tagged. This saves bandwidth and client parsing, not the database query. See `docs/performance.md`. (#1244)
- `GET /tenant/usage` now reports watch-list headroom, so a tenant can see how close it is to a cap before `POST /tenant/watch` starts returning 429. `watched_contracts: {held, limit}` is the tenant's own watch list against `max_watched_contracts` (`limit` is null when it has no cap), counted by the same query the add path enforces the cap with. The instance-wide cap is exposed to a tenant only as the boolean `instance_watch_list_full`, because the instance total is aggregate usage across every tenant; the operator view, `GET /admin/tenants/{id}/usage`, carries the same tenant figures plus `instance_watched_contracts: {held, limit}`. The OpenAPI spec, the generated client and `docs/multi-tenancy.md` are updated. (#1157)
- A skipped test dependency is now impossible to miss. `internal/testskip` gives the suite one convention for an external dependency a test can run without: the skip prints a banner naming what did not run, why, what the skip cost and how to get the dependency, and every make target (`make test`, `make test-fast`, `make test-ci`, `make test-db`, `make test-integration`, `make cover*`, and therefore `make ci`) runs `make test-prereqs` first so the banner appears in the default output rather than only under `go test -v`. The Helm chart's golden tests and the store's database-backed conformance suite use the same mechanism, so there is one wording for the whole suite. `SOROTRAIL_REQUIRE_HELM=1` (or `SOROTRAIL_REQUIRE_POSTGRES=1`) turns the skip into a failure: CI's `helm` job sets it and now runs the chart's golden tests, which it previously never did — the job installed Helm but the Go tests that need it were never invoked.
- `TestRender_ConfigValuesReachThePod` in `deploy/helm/sorotrail/render_test.go` is the guard for a configuration variable that never reaches the pod: every value under the chart's `config:` block must be wired into the ConfigMap, and every variable the ConfigMap renders must be one the application actually reads. Helm accepts an unused value silently, so without this guard a new setting could sit in the chart doing nothing.
- Every entry in the README's configuration table now carries a Reload column: `SIGHUP` for the two values the running indexer re-reads and applies live (`POLL_INTERVAL`, `LOG_LEVEL`), `restart` for the hundred values read exactly once at startup. `internal/config` pins the classification against the real reload path in `cmd/sorotrail` — the set `applyReload` applies must equal the reloadable set, and the set `warnIgnoredTopologyChanges` announces must equal the restart-required topology set — and against the table itself, so a value can no longer be added, reloaded or renamed without its restart semantics being stated.
- [docs/metrics.md](docs/metrics.md) — the metrics catalogue: every Prometheus metric SoroTrail exports, with its type, its labels and their closed value sets, the help text `/metrics` serves, and what the number means to an operator. It is generated from a table in `internal/metrics` that is checked against `metrics.go`'s declarations and against what the registries actually serve, so renaming, removing or adding a metric without documenting it fails the test; the same table pins the Prometheus naming rules and the no-ids-in-labels rule, and drives a cardinality test proving client-shaped values never reach a label.
- [docs/errors.md](docs/errors.md) — the API's error catalogue: every failure condition the server can produce, the status it answers with, the exact message a client sees, and the operations it can surface on. It is generated from `internal/api/error_catalogue_test.go`, which cross-checks it against the handlers' source and the shipped OpenAPI spec in both directions, so an undocumented new error — or a stale entry for one the server can no longer produce — fails the test. The spec gained the statuses it was missing along the way: 501 on the API-key and contract endpoints, 503 on the contract spec-override endpoints, 403 on the subscription create/update endpoints, and 426 for a refused websocket handshake.

### Changed

- CI caches Go modules and build output with an explicit key that includes the Go version, `go.sum` and the build-tag flavour, so the `-tags=integration` job no longer shares a single cache slot with the untagged jobs.
- The integration-tagged suite now runs against a matrix of Postgres 15 and 16 rather than 16 alone, and the aggregate `integration` check still reports the name branch tooling expects.
- Migration version-number collisions are gated by their own database-free `migrations` job and `make migrations-check`, ahead of the suites one collision would otherwise break. [CONTRIBUTING.md](CONTRIBUTING.md) documents how to pick the next version number.
- Dependency CVEs are reported by a new `vulncheck` CI job, which runs `govulncheck ./...` on pull requests and on pushes to `main` and fails when a known vulnerability is reachable from the module's own code. The module's minimum Go moves to 1.26.9, the newest 1.26 patch, because govulncheck reports standard-library advisories against the exact patch the `go` directive names and 1.26.0 carried 36 reachable ones.

### Fixed

- The ClickHouse contract-metadata surface refuses instead of answering with a value that reads as success. `ListContractIDs`, `GetContractMeta`, `UpsertContractMeta`, `CountContractEvents` and `ListContractsNeedingRefresh` all return `ErrUnsupported` (the metadata reads previously returned an empty result and the write returned nil, so an enrichment pipeline reported success forever while storing nothing, with no log line or metric to say so). `GET /contracts/{id}/stats` answers 501 rather than a 500 that reads as a fault in the server, and the metadata it would have attached is simply absent — see [docs/clickhouse.md](docs/clickhouse.md).
- Transient transport failures are classified in one place, structurally. The two hand-rolled `isTransientHTTP` copies — one in `internal/rpc`, one in `cmd/sorotrail` — matched on the host operating system's error wording, so the answer depended on the platform the binary ran on: POSIX reports a refused connection as "connection refused" and Windows as "No connection could be made because the target machine actively refused it", which matched no fragment. `internal/rpc.IsTransientHTTP` now recognises a refused connection, a DNS failure, a reset, a timeout and an unexpected EOF through the error tree (`net.Error`, `*net.OpError`, `*net.DNSError`, `io.EOF`, `context.DeadlineExceeded`, `syscall.ECONNREFUSED`, `syscall.ECONNRESET`) instead of through the rendered message, and the backfill uses it. The divergence that motivated the change is closed: a DNS failure was retried by the ingester and fatal to the backfill, and is now retried by both. The substring fallback stays as a last resort for errors with no typed cause.
- The store contract issues #525 and #526 describe — audit state that round-trips with a monotonic `SaveAuditStateIfGreater`, findings the auditor records and retrieves through `ListOpenFindingsByRange`, and watched-contract mutations the list endpoint reflects — is now enforced by the shared store conformance suite instead of being skipped. `WatchedContracts` gained the removal half of its lifecycle (remove → list reflects it, a repeat remove reads as `ErrNotFound`, re-adding a removed contract brings it back), and two new cases pin the auditor's half: `AuditStateRoundTrip` (a never-audited network reads as `ErrNotFound` rather than ledger 0, a save round-trips, a lower candidate never regresses the marker, and the first advance creates the row) and `AuditFindings` (record → retrieve over its ledger range → update persists retry bookkeeping → a repaired finding retires from the open lookup → updating an unknown id stays a no-op). The ClickHouse registration, which still declared *every* behavioural test unsupported on the grounds that its methods were zero-value stubs, now opts in exactly those three, and the ClickHouse test factory clears the tables between runs the way the Postgres factory truncates (`audit_findings` included), so a reused server cannot flake an exact-set assertion.
- `Postgres.ListOpenFindingsByRange` reads `last_error` through a pointer instead of a plain `string`. The column is NULL by design (`RecordAuditFinding` leaves it unset until a repair attempt fails, and `nullableString` writes NULL back for an emptied message), so on Postgres every read of a finding before its first failed repair — including the finding the auditor had just recorded — aborted with `cannot scan NULL into *string` instead of returning it. SQLite's shared `scanAuditFinding` already read it through a pointer; the new `AuditFindings` conformance case is what surfaced the divergence.
- The in-process event broker in `internal/api` honours every filter field the REST query path does: a subscription with `topic0`–`topic3`, `topic_contains`, `has_value`, `tx_hash`, `network`, `contract_ids`, `contract_id_prefix`, `in_successful_call`, `tx_index`, `op_index`, `from_time` or `to_time` no longer receives events the equivalent `GET /events` query excludes. The shared table of filter cases that proves it is run against both halves, one of them against a real Postgres. The live `/events/ws` broadcaster in `internal/broadcast` keeps its own, narrower matcher and is unchanged — see [docs/subscriptions.md](docs/subscriptions.md).
